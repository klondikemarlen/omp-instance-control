# OMP Integration

Own extension registration for main interactive instances, lifecycle request admission, and invoking supported public OMP host APIs.

`index.js` registers the canonical `/ompi` command and claims one binding through the public extension event bus, avoiding duplicate registration from installed/injected paths. Only launcher-managed main TUI instances publish control endpoints. It calls public `ctx.shutdown()` after acknowledgement, leaving OMP core to decide settlement, persist the transcript, tear down, and release the terminal.

`command.js` mirrors native `ompi instances` actions, options, and profile scope. Ordinary OMP can control wrapped peers without advertising self-restart. Peer observation uses the shared JS client; a self-selected snapshot returns acceptance without waiting. Public widgets and in-memory host keybindings own progress/cancellation; autocomplete caches online peers per scope and configured profile names from the Linux boundary, refreshing through listing and lifecycle events. The host completion callback remains synchronous.

Explicit `/ompi instances cleanup` invokes the Linux transport's conservative legacy cleanup, with `--profile`/`--json` and action/profile autocomplete. It does not invoke OMP shutdown or restart and can run from ordinary OMP. Listing and completion never remove records.

`take-over.js` captures the public host session ID/file/cwd, delegates command preparation to [`../linux/take-over.js`](../linux/take-over.js), and rejects session changes during that asynchronous work. `command.js` displays the result in a public confirmation dialog, revalidates after confirmation, records preparation through `appendEntry`, then calls `ctx.shutdown()`. Cancellation and preparation failures never request shutdown. The dialog is required so teardown cannot hide the command before the user copies it; the user alone performs the subsequent shell paste.

Recovery captures public session ID/file/cwd at lifecycle boundaries and invalidates a predecessor when the current session cannot be captured. Missing new transcripts remain quietly pending. Active managed slots are recorded in scoped recovery checkpoints; shutdown excludes the closing slot. `recovery-command.js` owns selection, optional names, history/import/export feedback, and the copy-before-exit interaction. `command.js` registers the public command and caches completion candidates. Linux owns persistence, ownership checks, and scope-anchored command preparation. Lookup uses the launch-anchored scope, not the current ticket worktree; ordinary OMP remains a peer-control client rather than an automatically captured session.

Linux transport belongs in [`../linux/`](../linux/README.md); wire semantics belong in [`../protocol/`](../protocol/README.md).

`launcher-context.js` validates native `ompi` launch identity and captures the current session/cwd during shutdown. The Linux launcher owns relaunch after successful exit, not OMP settlement. Ambiguous custom flag arity makes controlled restart explicitly unavailable without blocking standard OMP invocation. The one explicit private compatibility dependency reads OMP's parsed extension-flag map at `session_start`, validates its shape, and refuses restart for built-in collisions or missing metadata. No private imports or lifecycle keystroke injection are used. See [host dependency and selected workaround](../CONCEPTS.md#host-api-dependency) and [upstream removal criteria](../README.md#temporary-ownership-and-upstream-removal).
